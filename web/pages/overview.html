Overview

Why apexFMP exists

apexFMP was created to solve a fundamental problem in many FileMaker environments: the interface was often constrained by layout-driven development, custom object logic, and a closed ecosystem that did not align well with modern software practices.

The result is a FileMaker-first architecture where the database remains the system of record, but the UI is authored in a modern web-native way. HTML, CSS, and JavaScript handle the interface. FileMaker handles the business rules, data integrity, workflow, and security model.

This creates a cleaner operating model: better UI control, stronger code review, clearer contracts between front end and data, and a path toward team workflows that are more common in the broader software stack.

Core principles

  • FileMaker remains the source of truth for data and process
  • HTML/CSS/JS provide the interface layer
  • FQL and JSON define the data contract
  • Merge variables inject dynamic content into templates
  • Web viewers render the final experience
